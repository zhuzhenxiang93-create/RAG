# 生成 Bad Case

评测范围：同一 20 条 validation Smoke；无检索证据；目标由确定性模板构造且未人工审核。

## Prompt Baseline

- JSON 可解析率（按项目 Schema）：0
- Schema 通过率：0
- 罪名字段 Micro-F1：0

输出本身通常是合法的通用 JSON，但字段为“罪名候选、关键事实、缺失信息、置信度、人工复核标记”等自定义中文名称，且字段类型在字符串、列表和对象间变化，无法通过项目英文键名与类型契约。

## 100 条 SFT Smoke Adapter

- JSON 可解析率（按项目 Schema）：0
- Schema 通过率：0
- 罪名字段 Micro-F1：0
- 20 条耗时：364.4 秒；多数输出走满 384 token

Adapter 仍沿用中文键名，说明 100 条训练不足以覆盖格式行为；它也没有稳定学习 EOS。该结果没有被包装成 SFT 提升。

## 下一轮最小改动

1. 从训练集构造更大规模、长度分层的 SFT Pilot；
2. 增加 Schema 字段与 EOS 的定向样本；
3. 将检索证据和引用候选真正放入输入；
4. 人工审核独立生成测试集；
5. SFT 稳定后再判断 DPO，不直接加入 GRPO。
