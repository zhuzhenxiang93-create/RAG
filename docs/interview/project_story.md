# LegalMind-RAG 项目讲解主线（20–30 分钟）

## 1. 一句话定义

这是一个面向匿名刑事案件事实的证据约束分析系统：先预测候选罪名，再检索法条和训练集历史案例，最后输出可校验的结构化分析；任何低置信分类或无依据引用都会触发人工复核。

## 2. 为什么单纯分类不够

旧项目只输出罪名。面试中我会先说明三个缺口：标签没有解释；相似罪名依赖行为、主观意图和结果等细节；模型无法说明采用了哪条法条、参考了哪件案例。于是我把任务拆成分类、法条检索、类案检索、Reranker、生成和引用校验六个模块，每个模块都有独立输入、指标和 Bad Case。

## 3. 数据从哪里来

服务器现有 `train_data.jsonl` 是 CAIL2018 历史派生数据，154,592 条，文件 SHA256 已记录。它保留事实、罪名和量刑，缺失原始法条字段；下载来源与许可在这台服务器上无法完整追溯，所以状态是 `legacy_local_file_unverified`。我没有用 748,203 条 `rest_data` 强行扩充，因为它来源未明、分布偏斜且和训练文件有重叠。

这个回答的重点是承认数据边界。项目可以训练罪名分类，但正式发布和法条监督训练必须回到 CAIL 官方原始文件。

## 4. 数据有什么问题

主要问题有重复案件、同案跨集合、显式罪名结论泄漏、长尾、多标签、长文本和派生字段丢失。旧 split 经 NFKC 和空白归一化后存在 train-validation 13 条、train-test 21 条、validation-test 1 条文本重叠。v2 按规范化事实哈希形成案件族，再以案件族切分，三个集合的精确、规范化文本与案件族重叠都为 0。

## 5. 标签泄漏怎么处理

起诉书末尾经常出现“构成某罪”“应以某罪追究”等直接答案。我用规则定位并遮蔽结论段，同时保留命中数和清理前后哈希。v2 中 train/validation/test 分别命中 58,189/7,247/7,220 条。这个比例较高，是下一轮人工抽检重点；规则不能被描述成已由法律专家验证。

## 6. 数据如何切分

标签映射只从训练集建立。去重后的案件族按固定 seed 分组，尽量保持多标签分布，不复制长尾样本。最终 120,393/15,032/15,097，202 类。测试集不参与阈值、Prompt 或超参数调整。

## 7. 为什么使用 QLoRA

Qwen3-4B 全参数 BF16 训练需要约 8 GB 权重，还要保存梯度、优化器和激活，24 GB 4090D 很难在 2,048 token 上稳定训练。QLoRA 把冻结基座以 NF4 4-bit 加载，只训练 LoRA 低秩增量；`r=16/alpha=32/dropout=0.05`，目标为 `all-linear`。选择依据是显存约束和可独立保存 Adapter，不是声称 QLoRA 一定优于 LoRA。

## 8. LoRA 加在哪些层

当前配置为 `all-linear`，覆盖注意力投影和 MLP 线性层；分类头通过 PEFT 的可保存模块保留。rank 16 是容量与显存的起点，尚未做 rank 8/16/32 的 Full 消融，所以不会说 16 最优。

## 9. max_length 怎么决定

先用 Qwen3 tokenizer 统计 token 分布，再结合 4090D 压力测试确定 2,048。代码同时支持前截断、Head+Tail 与句界事实选择。句界策略只看事实线索，不读取金标。三种策略已经可运行，但 Full Micro-F1 消融仍待测。

## 10. 如何减少 Padding

我没有做让不同样本互相可见的 Batch 拼接。分类任务使用动态 Padding，只 pad 到批内最长序列，再用 LengthGroupedSampler 按长度分桶。2,000 条审计中，固定长度 Padding Ratio 0.8346，随机动态 0.4671，动态加分桶 0.0139。

## 11. Batch Size 怎么决定

保持最大长度和有效 batch 32，只改变 micro batch：2/16 峰值 9.30 GiB；4/8 峰值 15.24 GiB；8/4 在 21.72 GiB 已分配附近 OOM。最终选择 4+8，依据是实测余量，不是“显存没满就继续加”。

## 12. 分类结果怎么看

Majority 验证 Micro-F1 0.0572，char TF-IDF+SGD 0.8092。历史 10K QLoRA 的验证/独立测试 Micro-F1 是 0.8332/0.8296；这是覆盖 202 类的历史分层实验，不冒充 v2 Full。v2 的 1,000/100 Smoke 只有 0.0073，因为训练太少且只用于验证链路。

## 13. 为什么需要检索

分类输出无法提供依据，而且相似事实不等于相同罪名。类案库只用 train split 构建，120,393 案、128,107 Chunk；验证和测试完全不进入索引。法条库来自政府公开页面，解析为 452 个唯一条号，状态保持自动下载、未人工逐条审核。

## 14. Chunk 怎么切

先按中文句界分段，再按 tokenizer 控制在 1,024 token，保留 128 token overlap。Chunk 保留父 `case_id`、索引、字符范围、split、罪名和文本哈希。这样检索局部事实，同时可以回到完整案件；固定字符截断会切断行为与结果关系。

## 15. 为什么做 BM25、Dense 和 Hybrid

BM25 对金额、工具和专有表达敏感；Dense 能召回词面不同、法律语义相近的事实；RRF 避免直接比较两个不可校准的分数。Pilot 中 Dense nDCG@10 0.9863，高于 Hybrid 0.9013，说明组合并不天然更好。当前代理 qrels 是共享罪名，必须补人工法律相关性标注再做最终选择。

## 16. 难负样本怎么构造

从 5,000 个 train 查询的 BM25 高排候选中挖掘，记录 `query_id/positive_id/negative_id/negative_type`。实际得到 14,536 个三元组、覆盖 4,882 个查询，包括同罪名不同行为 4,135、金额差异 2,710、主观意图差异 2,652、共同/单独犯罪差异 1,741 等 8 类。validation 与 test 没参与训练难负构造，记录全部是 `unreviewed`。

## 17. Reranker 解决了什么

预训练 Qwen3-Reranker-0.6B 对 Hybrid Top-20 逐对打分。Pilot 中 Hybrid nDCG@10 从 0.9013 到 0.9467，但仍低于 Dense 0.9863。这个结果让我保留可配置 Reranker，同时不在默认结论中预设它必然有效。领域难负微调仍待运行。

## 18. SFT 数据怎么构造

v3.1 只从 train/validation 构造 4,500/550 条简化 JSON 数据。普通样本的罪名来自原始标签，关键事实由确定性句界函数提取；额外加入 500/50 条确定性信息不足变体，目标为空罪名、低置信度并人工复核。全部记录 `unreviewed`，来源案件跨 split 重叠为 0，test 使用数为 0。Assistant-only mask 已用真实 tokenizer 验证。

## 19. 如何检查幻觉

输出先通过 Pydantic JSON Schema，再逐项检查 `similar_cases.case_id` 和 `relevant_articles` 是否出现在本次检索上下文。低置信分类状态为 `uncertain_below_threshold`；没有足够证据时写入 `missing_information` 并设置 `requires_manual_review=true`。

## 20. SFT 做到了什么

100/20 Smoke 的训练链路完成，峰值 9.46 GiB。重新区分“JSON 可解析”和“Schema 匹配”后，20 条 Prompt/SFT Smoke 的原始 JSON 可解析率是 1.00/0.95，旧 Full Schema 通过率仍为 0。失败集中在中文字段名、中文置信度、罪名后缀和 1 条截断。规范化修复后的简化 Schema 通过率是 1.00/0.95，罪名 Micro-F1 为 0.9091/0.9048；样本太少，只用于诊断。下一步用 v3.1 严格字段数据做同 validation Pilot。

## 21. 为什么没有直接做 GRPO

当前 SFT 还没稳定，检索 qrels 没人工审核，法条监督缺失，也没有可信 chosen/rejected 对。奖励即使能写出来，也会优化一个不可靠的链路。满足格式稳定、引用可验证和偏好错误可重复之后，优先尝试小规模 DPO。

## 22. 最大的 Bad Case

端到端示例中，历史分类器的最高概率仍低于对应阈值，旧逻辑会回退到五个标签并把它们当普通预测。修复后明确返回 `uncertain_below_threshold`、`used_fallback` 和最大概率，只把前三个候选交给分析并强制人工复核。法条 BM25 也会被“犯罪嫌疑人”等程序词干扰，因此改成候选罪名优先、事实只补一条情节法条。

## 23. 项目局限

最重要的局限是原始 CAIL 来源与法条字段未恢复、代理 qrels 未人工审核、v2 Full 分类和 Full SFT 未跑、法条文本未由专业人员逐条核验。这些限制都写进 Manifest 和 README。

## 24. 下一步

当前 v2 Full QLoRA 已从 checkpoint-500 继续训练。GPU 释放后依次运行长文本受控消融、领域 Reranker Pilot 和 SFT v3.1 Pilot。200 条检索查询及人工审核 CSV 已生成，仍需要用户或法律专业人员实际审核；官方 CAIL 来源与法条字段仍需恢复。只有 SFT 后仍存在明确偏好错误时再做 DPO。
