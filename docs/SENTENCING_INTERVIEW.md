# 结构化量刑：面试讲解

## 三分钟版本

这个项目最初是一个中文刑事案件罪名多标签分类与类案检索原型。我在数据审计时发现，原始
CAIL 数据包含刑期、死刑、无期和罚金，但旧处理契约丢掉了罚金，因此原系统只能回答“可能
是什么罪”，不能完整回答“历史案件中可能出现什么量刑结果”。

我首先把任务边界改成“案件事实 + 可选罪名 -> 结构化历史量刑预测”。只给罪名时，系统不会
编造刑期，而是提示还缺少金额、自首、退赃、谅解和累犯等量刑事实。数据侧建立 v2.1 契约，
区分罚金缺失、零罚金和正罚金，并在去重时审计相同事实但判决不同的冲突。训练前还脱敏
“判处有期徒刑八个月、并处罚金一千元”等判决结论，防止模型偷看答案，同时保留犯罪金额、
退赃和自首等合法预测特征。

模型采用共享字符 n-gram 表示加分层多任务头：刑罚类型、刑期区间与月份、是否罚金、罚金
区间与金额。罚金用两阶段结构，因为“是否判罚”和“罚多少”是不同分布。推理后加入硬约束：
死刑或无期不能同时返回有期徒刑月数，不罚金就不能返回金额。最后用训练集类案索引提供脱敏
证据并辅助置信度判断。

这个实现的重点不是追求一个漂亮但不可解释的数字，而是数据不丢失、无目标泄漏、结果一致、
指标可复现、边界说清楚。现有数据不能可靠区分拘役、管制，也没有可靠缓刑标签，所以系统明确
返回 unknown，而不是伪造功能。

## 简历描述

- 将 LegalMind-RAG 从罪名分类扩展为案件事实驱动的结构化量刑研究系统，设计刑罚类型、刑期、
  罚金两阶段预测和一致性约束，并接入脱敏类案证据。
- 重构 CAIL 数据契约与 v2.1 构建流程，保留罚金标签，加入判决结论泄漏清洗、跨集合去重和重复
  事实量刑冲突审计，建立可复现的数据/模型/评估版本。
- 实现 Python、CLI 与可选 FastAPI 接口，输出置信度、人工复核标记和法律风险声明；对数据无法
  支撑的拘役、管制和缓刑预测明确降级。
