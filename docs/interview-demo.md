# 面试演示指南

## 一键启动

在项目根目录执行：

```powershell
.\scripts\run-demo.ps1
```

脚本使用项目内 `.venv`，启动服务并打开 `http://127.0.0.1:8000/ui/`。
演示结束后关闭脚本窗口或按 `Ctrl+C`。

## 首次演示准备

1. 点击右上角“载入演示语料”。
2. 等待提示“已导入 7 篇演示文档，并完成索引”。
3. 确认首页显示文档数量、子块数量和 Lite 模式。

演示初始化接口是幂等的：相同内容按 SHA-256 跳过，不会重复导入。该接口只在
Lite 模式开放，Full 模式返回 403。

## 五分钟讲解顺序

### 0:00–0:40 业务问题

“企业知识问答的难点不只是接一个大模型，而是异构文档结构丢失、精确编号和语义
问题需要不同检索策略、客服问题需要先识别业务意图、不同版本制度相互冲突，以及模型在证据不足时仍可能回答。
因此我把两个旧项目重构成了一个领域无关的企业文档智能分析平台。”

### 0:40–1:30 文档接入

进入“文档库”，展示：

- PDF、DOCX、XLSX、TXT、Markdown 统一上传；
- 页码、章节和表格结构保留；
- Parent-Child 分块；
- 文件摘要、结构统计与 SHA-256 内容追踪。

可以打开一篇文档，展示章节定位和子块预览。

### 1:30–3:10 可信问答

先提问：

> SEV-1 生产事故要求多少分钟内响应？

展示答案、置信度五维拆解、Query Router、BM25/Dense 权重、证据引用和耗时。
同时指出右侧显示领域、意图、路由置信度和知识库建议；Lite 演示使用可解释关键词
基线，Full 模式接口可替换为 MASSIVE 上训练的 Qwen2.5 LoRA。

然后提问：

> 比较 2024 和 2025 制度中用户操作日志保留期限的差异。

重点展示系统发现数值或版本冲突后返回 `clarify`，而不是选择其中一个版本编造确定
答案。

最后提问：

> 量子发动机的最大推力是多少？

展示知识库缺少证据时返回 `abstain`。

### 3:10–4:20 可复现实验

进入“评测中心”运行 Lite V1：

- 7 篇人工编写文档；
- 14 个标注问题，其中 12 个可回答；
- BM25、Lite Dense、RRF、RRF + Lite Reranker、Adaptive 消融；
- MRR、Recall@K、nDCG@K、延迟、拒答、冲突和引用指标；
- 每次运行保存原始预测 JSON。

主动说明真实结果：当前小型语料中精确术语很多，BM25 优于哈希式 Lite Dense 和
Adaptive。Lite Dense 不是语义 Embedding，因此不把该结果包装成“混合检索提升”。

### 4:20–5:00 工程化与扩展

“主链路无密钥即可在 CPU 运行；通用意图 LoRA 和历史法律模型通过插件延迟加载。API、
存储、解析、检索、证据分析和评测相互解耦。下一步会在独立校准集上确定置信度阈值，
接入真实 Embedding 与 Cross-Encoder，并扩大带页级证据标注的测试集。”

## 面试官可能追问

### 为什么不直接用向量检索？

企业文档包含工单号、制度编号、日期和指标名，精确词项对这些问题非常重要。
Query Router 根据问题类型调整通道权重，评测结果也表明不能假设 Dense 一定优于
BM25。

### 置信度是否来自大模型自报？

不是。当前置信度由证据相关性、多通道一致性、排名间隔、引用覆盖率和冲突惩罚组成，
每个分量都在界面和 API 中返回。

### 指标为什么这么高？

这是 7 篇文档、14 个问题的小型工程回归集，不是生产指标。它的作用是确保管线可复现
并暴露失败模式。项目明确记录数据规模、原始预测和后续待测项。

### LoRA 为什么不是一个孤立的分类 Demo？

分类结果进入 `RetrievalPlan`，影响知识库建议、BM25/Dense 权重和是否宽召回；低于
阈值会回退全库。因此评测分三层：分类 Accuracy/Macro-F1、检索 Recall/MRR，以及
最终引用与拒答指标，而不是只报告分类分数。

### 为什么选 MASSIVE？

它覆盖多语言、18 个领域和 60 个意图，包含中文并提供标准数据划分，适合展示中文
单语和中英迁移实验。项目保存数据 revision、SHA-256、随机种子和逐条预测。

### 法律能力是否限制了项目场景？

不会。法律罪名分类被降级为历史可选插件；主系统面向客服知识、企业制度、技术文档等
通用场景，核心微调任务已经变为通用意图识别和 RAG 路由。
