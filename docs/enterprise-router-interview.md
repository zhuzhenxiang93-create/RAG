# LoRA 项目三分钟面试讲解

## 30 秒：问题

“我使用 EnterpriseRAG-Bench 研究多源企业知识检索。数据分布在 Slack、邮件、GitHub、
项目管理和会议纪要等九类来源。固定全库检索会引入大量无关文档，而规则路由难以覆盖
语义表达和跨文档问题。”

## 60 秒：方法

“我基于 Qwen 指令模型设计了一个生成式 LoRA 路由器。输入用户问题，输出严格 JSON，
包括问题类型、目标来源、是否跨文档、是否检查冲突和检索深度。LoRA 注入 Attention
的 q/k/v/o 投影层，基础模型冻结；训练时屏蔽 Prompt Token 的 Loss，只监督目标 JSON。
路由结果实际控制 BM25 与 Dense 检索范围，而不是独立展示一个分类结果。”

## 45 秒：数据规范

“官方 500 道题有明确的 benchmark canary，不能进入训练集。我用不读取官方题目的
确定性模板生成器创建 Northstar Labs 独立训练公司，覆盖 10 类问题和 9 类来源；对
训练集和 Redwood 测试集做 ID、规范化文本哈希与两两 token Jaccard 检查。最大
Jaccard 为 0.233333，官方测试集只用于最终盲测。”

## 45 秒：实验

“我比较全来源固定检索、基础模型零样本路由、LoRA 路由和 Oracle 路由，并固定相同的
检索器和 Top-K。路由层评估 JSON 合法率、来源多标签 F1；检索层评估 Recall@10、MRR、
nDCG@10、候选数量和延迟。这样可以区分‘分类指标变好’和‘RAG 端到端真正受益’。”

## 面试官追问

### 为什么不用普通分类器？

普通分类器适合固定标签，但这里同时包含单标签、多标签、布尔字段和未来可扩展参数。
生成式路由能统一输出检索计划；代价是需要 Schema 校验、JSON 合法率和失败回退。

### 为什么不用提示词直接让基础模型路由？

基础模型零样本路由就是实验基线。只有当 LoRA 在独立测试集上显著改善字段指标或下游
检索指标时，微调才有必要；否则应保留零样本方案。

### LoRA 为什么可能降低 Recall？

如果来源预测漏掉 Gold 来源，硬过滤会直接丢失相关文档。因此系统记录 Oracle 上界，
并设计低置信度全源回退和二阶段扩检。正式结论必须同时报告 Recall 与延迟。

### 为什么不微调答案生成？

企业知识持续变化且需要引用。把事实写入模型参数会过期，难以追踪来源。LoRA 学习查询
策略，知识仍从文档库动态获取。

### 你做了哪些真正的工程工作？

包括数据转换、训练 Prompt、Prompt Loss Mask、PEFT 配置、Adapter 保存加载、严格 JSON
解析、污染检测、多任务指标、基础模型/LoRA统一评测，以及路由对下游检索的消融脚本。

## 本次真实结果怎么讲

> “V2 QLoRA 在官方 500 题上将严格 JSON 合法率从基础模型的 0% 提高到 99.4%，但来源
> Micro-F1 只有 0.3237。硬路由把 45,278 文档 BM25 的平均延迟从 248.27 ms 降到
> 145.62 ms，同时 Recall@10 从 0.5827 降到 0.3844；Oracle 路由可达 0.7848。
> 因此我的结论不是强行宣称提升，而是证明当前跨公司模板训练存在分布偏移，硬过滤不
> 安全；下一版应做同域非金文档问题生成和低置信度回退。”

这个回答的重点是能区分格式学习、语义泛化和下游业务指标，并基于失败结果做系统设计。
